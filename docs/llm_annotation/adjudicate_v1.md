# 逐处裁决说明（给复核模型，v1）

你是复核员。附件有两个文件：《中文网络小说名字识别标注规则》（guide.md，下称“规则”）和要裁决的地方（questions.md）。请逐处裁决，只输出 JSON。

## 只能依据什么

- 规则、questions.md 里给的原文段落，以及每组前面“书的知识”。
- “书的知识”是读过全书的人写的原话，当作有出处的跨章证据（规则 E1），用来确认对象是什么、在书里怎么被称呼。
- 要不要标、框多长、标哪一类，按规则判断；原话里对标法的倾向要按规则核对，不能直接当结论。
- 组里写了“类型已由读者确定”的，类型照读者的定，只裁决要不要标、框多长。
- 有的组附了考卷别处同类写法的现有标法，只用来参考是否前后一致（规则 E6）；每一处仍然按本处用法判断（规则 C1）。
- 不要凭记忆补充小说的情节、人物或设定，不要上网查。

## 怎么裁决

- 每一处单独判断。同一组里的各处可以有不同结果（规则 C1：类型依据本次指称）。
- 每一处给出一个结果：
  - `type`：六类之一（person、organization、location、dungeon、item、trait），或 `"none"`（不标），或 `"pending"`（按规则和给你的材料仍然无法裁决）。
  - `text`：标的时候写要框的原文，必须是【】里那段原文中连续的一段，一字不差（规则 B 部分：外加称谓、引号、修饰不框；平面标注，不嵌套）。`type` 是 `"none"` 或 `"pending"` 时写空字符串。
  - `rule`：依据的规则条款，如 `"A1"`、`"A7"`、`"B2"`、`"C1"`、`"E4"`。
  - `reason`：一句话理由。
- `pending` 只在规则确实给不出答案时用，不要用来回避。

## 输出格式

只输出一个 JSON 对象，前后不要加任何文字：

```json
{
  "version": "adjudicate_v1",
  "decisions": [
    {"id": "q99-1", "type": "person", "text": "林小雨", "rule": "A6", "reason": "本处是人物昵称"},
    {"id": "q99-2", "type": "none", "text": "", "rule": "A1", "reason": "本处是泛称"}
  ]
}
```

（例子里的名字都是虚构的。）questions.md 里每个“###”小标题都有一个形如 q01-1 的编号，每个编号各写一条，不多不少；“##”组标题里的 q01 这类编号不用写。
