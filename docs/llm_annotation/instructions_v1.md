# 名字识别标注说明（给 GPT，v1）

你是一名标注员。请按附件《中文网络小说名字识别标注规则》（下称“规则”）给附件里的章节做名字标注，只输出 JSON。

## 只能依据什么

- 只依据规则和给你的章节原文。
- 不要凭记忆补充这本小说的情节、人物、道具或设定，也不要上网查。你可能读过这本书，但这次只看给你的文字。
- 只靠给你的文字确定不了“是不是名字”或“哪一类”的，不要猜，标待审（见下）。

## 标什么

- 规则里的六类：person、organization、location、dungeon、item、trait。item 指有名字的游戏物品（道具、药剂、车票、系统认可的任务物品等），不只是道具。
- 每一处出现都要单独列出。同一个名字在一章里出现二十次，就列二十条。漏列就是漏标，主角的名字也不例外。
- 平面标注：一处只标一个范围、一个类型，范围之间不重叠、不嵌套。
- 范围必须和原文一字不差。名称外的引号、书名号、括号、序号和标点不框；姓名后面的称谓不框（规则 B1）。
- 不是名字的（泛称、代词、普通物件、描述、等级加类别等，见规则 A 部分）不用列出。

## 待审

规则允许、本章文字也确实不够判断时，才标待审：`type` 写 `null`，`pending` 写 `true`，并写清楚：

- `stuck`：卡在哪一步，可多选：`"qualification"`（是不是名字）、`"boundary"`（框多长）、`"type"`（哪一类）。
- `candidates`：候选标法，例如 `"item / 不标"`。
- `doubt`：一句话说明疑点；需要别的章节才能确定的，写“需要别章证据：……”。

待审不要滥用：规则能直接判的，直接标。

## 输出格式

只输出一个 JSON 对象，前后不要加任何文字：

```json
{
  "instructions_version": "v1",
  "guide_version": "1.1",
  "chapters": [
    {
      "chapter_id": "ch9999",
      "mentions": [
        {"paragraph_id": "p0001", "text": "林小雨", "occurrence": 1, "type": "person"},
        {"paragraph_id": "p0001", "text": "林小雨", "occurrence": 2, "type": "person"},
        {"paragraph_id": "p0003", "text": "灰塔城", "occurrence": 1, "type": "location"},
        {"paragraph_id": "p0005", "text": "回音铃", "occurrence": 1, "type": null, "pending": true,
         "stuck": ["type"], "candidates": "item / trait", "doubt": "本章只写了效果，没说是道具还是特性"}
      ]
    }
  ]
}
```

（例子里的名字都是虚构的。）

字段说明：

- `chapter_id`：原文里每章标题行写的编号，如 `ch0057`。
- `paragraph_id`：原文里每段开头方括号里的编号，如 `[p0001]`。
- `text`：名字原文，一字不差。
- `occurrence`：这串字在这一段里从左往右是第几次出现，从 1 开始数。同一段里这串字的每一次出现都要数，不管那一处标没标；有重叠出现时，每个起点各算一次。
- `type`：六类之一的英文代码；待审时写 `null`。
- `pending`、`stuck`、`candidates`、`doubt`：只有待审时写。
- `note`（可选）：难判断但已经决定的地方，用一句话写依据，引用规则条款，如“B1”。

## 输出前自查

1. 每条的 `text` 都能在对应段落里原样找到，`occurrence` 不超过它在该段里出现的次数。
2. 每个名字的每一次出现都列了。
3. `type` 只用六个英文代码，或待审时的 `null`。
4. 同一处没有重复列出，范围互不重叠。
5. 只输出 JSON。
